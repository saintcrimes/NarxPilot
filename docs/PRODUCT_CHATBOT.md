# Простой чат-бот вопросов и ответов о NarxPilot

> Уточнение на 31 октября 2026: корневой `bro24.md` содержит пример запроса к готовому внешнему backend. Добавляется необязательный серверный поставщик Bro24; локальная справка сохраняется как режим по умолчанию и fallback. Формат ответа и условия хранения переписки внешним сервисом не предоставлены. Живое подключение не проверено. Закупки и независимые аналитические AI-функции не меняются; отдельный backend чат-бота в NarxPilot не создаётся.

## 1. Назначение и объём

**Только помощь с продуктом:** отвечать на общие вопросы о NarxPilot. Не отдельный аналитический сервис и не автоматический продавец. Реализовать как небольшую дополнительную функцию P1 после стабильного пути закупки и аналитики. Готовность P0 не зависит от наличия чата, но статус реализации P1 должен быть указан честно.

Название в интерфейсе: «Помощь по NarxPilot». Для локальных ответов подпись: «Ответы из справки о продукте». Не называть локальный FAQ генеративным ИИ; при внешнем ответе явно указывать поставщика и передачу сообщения Bro24. Настройки внешнего backend и его API-ключ не показываются клиенту.

## 2. Что входит

Компактная кнопка «Помощь», окно диалога, 4–6 стартовых вопросов, текстовый ввод, ответы из утверждённой справки и ссылки на разделы приложения. Локальные заготовки — `examples/product_faq.json`. Это исходный контент для разработки, а не доказательство, что описанные функции уже работают.

Темы: поиск и сравнение одинаковых товаров, доставка и итоговая сумма, заявка/резерв/приёмка, обновление предложений, различие цены объявления и сделки, смысл графика и неполных данных, уведомления. Общий вопрос «почему меньше продаж не означает дешевле?» допустим. Анализ конкретной текущей ситуации чат не выполняет.

## 3. Чего нет

Нет самостоятельного анализа сделок, прогнозирования, рекомендаций купить/продать, формирования цены, доступа к персональным заказам и данных других пользователей. Нет создания/подтверждения/отмены заказов и изменения остатков. Нет ответов о постороннем проекте пользователя. NarxPilot не обучается на переписке; политика внешнего сервиса пока не описана. Не добавлять платёжные реквизиты, придуманные контакты, сроки доставки, условия возврата или юридические обещания.

Вопрос о текущей цене ведёт к каталогу/карточке товара. Вопрос «где мой заказ?» ведёт к авторизованному разделу заказов. Вопрос о прогнозе ведёт к аналитике с её собственными ограничениями. Справка не заменяет динамические данные.

## 4. Минимальная реализация

В web-приложении достаточно локального модуля: `FAQ widget → matchQuestion(text) → approved FAQ item / clarification / fallback`.

Готовая кнопка выбирает `faq_id` напрямую. Для свободного ввода использовать нормализацию регистра/пробелов/пунктуации и контролируемые варианты вопросов. При неопределённом соответствии лучше показать 2–3 подходящих вопроса, чем публиковать неверный ответ. Не считать один общий токен вроде «цена» достаточным доказательством совпадения. Запросы с актуальной ценой, личным статусом, действием или прогнозом направлять в соответствующий экран, не выдавая общий FAQ за ответ с живыми данными.

Для local не нужны LLM, RAG, векторное хранилище, агент или отдельный backend-сервис. Подключённая модель аналитических объяснений НЕ становится моделью FAQ автоматически. Внешний режим обращается к уже существующему Bro24 через сервер NarxPilot, без создания дублирующего backend чат-бота.

### Документированный запрос Bro24

Источник — `bro24.md`. Сервер отправляет POST на фиксированный адрес `https://dashboard.bro24.uz/api/v1/public/chat`, заголовок `X-API-Key` из серверной переменной `BRO24_API_KEY` и JSON:

```json
{"client_id":"<псевдоним клиента>","channel":"website","message":"<вопрос о NarxPilot>"}
```

`client_id` формируется HMAC на сервере; открытые идентификаторы пользователя/организации не передаются. Пример не задаёт полей `context`, `messages`, `conversation_id`, инструментов, webhooks или streaming — не добавлять их по предположению. Контекст продукта должен соответствовать общедоступной справке; способ настройки знаний во внешнем backend требуется подтвердить отдельно.

Пример ответа отсутствует. `BRO24_REPLY_JSON_PATH` задаёт явный путь к строковому тексту в ответе JSON после получения обезличенного примера. Значения по умолчанию вроде `reply`, `answer` или `message` не предполагаются. Без корректной настройки, при таймауте, HTTP-ошибке или неподходящем ответе используется обозначенный локальный fallback. Полученный текст выводится как текст, без выполнения HTML или действий.

## 5. Контент и честный fallback

У каждой записи: `id`, `question`, `variants`, `answer`, `category`, `source_section`, `links`. Ссылки ведут только в существующие внутренние маршруты; при ином роутинге Codex должен исправить их. Контент версионируется вместе с проектом. Неподтверждённую политику сервиса не публиковать.

Fallback: «В справке пока нет точного ответа на этот вопрос. Выберите одну из тем ниже или откройте нужный раздел платформы». Не обещать соединение с оператором, если такого канала нет. Не утверждать, что обращение уже отправлено.

Для первой версии русский текст соответствует остальному интерфейсу. Переводы добавляются отдельно после проверки; не обещать поддержку языков, которых нет в базе ответов.

## 6. Конфигурация, приватность и доступность

`CHATBOT_ENABLED=false` по умолчанию; отсутствующая переменная = false; `true` показывает виджет. Сервер разбирает флаг строго и передаёт клиенту только публичный boolean. Перезапуск/сборка описываются по реально созданной реализации. Флаг не управляет `ANALYTICS_MODE` и `LLM_PROVIDER`.

`CHATBOT_PROVIDER=local|bro24`, по умолчанию `local`. В local и при выключенном виджете внешних запросов нет. Для bro24 требуются серверный `BRO24_API_KEY` и явно заданный `BRO24_REPLY_JSON_PATH`; отсутствие настройки сохраняет локальную справку. Вызов ограничен таймаутом, а недоступность Bro24 не блокирует основной продукт. Ключ не добавляется в `NEXT_PUBLIC_*`, JSON сессии, исходники или журнал.

В NarxPilot история диалога хранится только в памяти текущей страницы. Перезагрузка и выход очищают локальную историю; простое закрытие/открытие виджета в пределах страницы может её сохранять. Не писать вопросы в серверные логи, стороннюю аналитику, localStorage и БД NarxPilot. В режиме bro24 текст сообщения передаётся внешнему сервису; его сроки хранения и удаление не подтверждены, поэтому очистка виджета не означает удаления внешней переписки. Ограничить длину сообщения 1000 символами и пояснить превышение; пользовательский ввод выводить как текст, не исполняемый HTML. Подпись: «Не отправляйте пароли и платёжные данные».

Ошибку виджета изолировать: закрывающийся FAQ не может блокировать оплату/заказ, график или навигацию. Поддержать клавиатуру, управление фокусом, доступные подписи и читаемость на телефоне. Отключённый виджет не оставляет пустую кнопку.

## 7. Проверка

Базовые проверки — раздел F в `ACCEPTANCE_TESTS.md`. Отдельно проверить отсутствие внешних запросов в local/disabled, контракт запроса Bro24, HMAC-псевдоним, обязательный путь ответа, таймаут, HTTP-ошибки и возврат к локальной справке. В отчёте различать проверки с подставленным HTTP-ответом и реальный вызов сервиса. Наличие JSON и спецификации не означает проверенное живое подключение.

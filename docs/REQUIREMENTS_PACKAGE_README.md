# NarxPilot — пакет требований для Codex и команды

**Версия:** 1.0 · 31 октября 2026 · рабочее название можно заменить.

Это техническое задание, архитектура и инструкции. **Это не готовое приложение:** Dockerfile, исходный код, миграции и исполняемые команды должен реализовать Codex по этому пакету. Работающая интеграция Bro24 и точность прогнозов этим пакетом не подтверждаются.

## Как использовать

1. Распакуйте пакет в отдельную папку проекта или перенесите его файлы в существующий репозиторий, не перезаписывая свои инструкции без проверки.
2. Откройте эту папку в Codex. Если репозиторий уже содержит `AGENTS.md`, объедините инструкции осознанно; не удаляйте действующие правила.
3. Передайте Codex текст `CODEX_PROMPT.md`. Он должен сначала изучить имеющийся код, затем реализовать обязательный вертикальный сценарий P0.
4. После реализации следуйте README, который Codex создаст для приложения, и проверяйте результат по `docs/ACCEPTANCE_TESTS.md`.
5. Добавьте исходный `Lumora_IT_Case_Tashkent_Case_D.pdf` в `references/` самостоятельно: в этом пакете он не дублируется.

## Состав

- `CODEX_PROMPT.md` — основной промпт, предназначенный для копирования в Codex.
- `AGENTS.md` — постоянные ограничения для работы с репозиторием.
- `docs/PRODUCT_REQUIREMENTS.md` — продукт, функции, шесть экранов, границы MVP.
- `docs/ANALYTICS_SPEC.md` — факты, показатели, качество данных, прогнозирование.
- `docs/ARCHITECTURE.md` — компоненты, сущности, события, API и безопасность.
- `docs/DEVELOPER_SETUP.md` — порядок реализации, конфигурация и контракт запуска.
- `docs/BRO24_INTEGRATION.md` — границы интеграции, демонстрационный и рабочий режимы.
- `docs/ACCEPTANCE_TESTS.md` — проверяемые критерии готовности.
- `docs/HACKATHON_PLAN.md` — все 12 заданий кейса, сценарий защиты, бизнес-допущения.
- `docs/SOURCES.md` — исходный кейс и проверенные внешние источники.
- `examples/.env.example` — проектируемая конфигурация; не содержит секретов.
- `examples/analytics_cases.json` — синтетические сценарии для обязательных тестов.

## Что установлено, а что предложено

**Из файла кейса:** требуется практичное цифровое или AI-решение о ценах, предложении и спросе для предпринимателей; 12 задач; 3–6 экранов; полный пользовательский сценарий; 3 минуты выступления и 2 минуты вопросов. Полноценный продукт не обязателен. Источник: S0.

**От пользователя:** покупка, сравнение цен, аналитика сделок/остатков/локаций, графики товарных цен, AI-помощник и предполагаемая интеграция Bro24. Распознавание фотографий не требуется.

**Предложения этого пакета:** узкий старт с B2B-закупок смартфонов в Ташкенте, технический стек, формулы, пороги качества, роли, правила безопасности, бизнес-модель. Их нужно проверить пилотом.

**Ограничение данных:** показатели относятся к подключённым источникам платформы, не автоматически ко всему рынку Ташкента или Узбекистана.

**Нерешённые внешние зависимости:** документированный API Bro24, реальные поставщики и договорённости об использовании их данных, точный размер адресуемого сегмента, рабочая платёжная интеграция. Они не должны блокировать явно маркированную демонстрацию.

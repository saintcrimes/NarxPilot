### Что покрыли реальные Python/PostgreSQL проверки

- 1000 − 500 − 200 − 100 = 200, падение объёма −60%/−50%, отсутствие ложного вывода о цене.
- Стабильная/растущая цена при снижении продаж; различие медианы и VWAP; Decimal-округление.
- Отсутствующие дни, предложение/резерв/отгрузка не как продажа, синтетика не в live.
- Частичный и полный возврат, позднее recorded_at, отсутствие утечки будущего.
- Перемещение, двойное объявление одного запаса, устаревший запас.
- Два полных окна, исключение сегодняшнего дня, изменение состава, концентрация, малые группы и аномалии.
- Применение SQL-миграций, запрет смешивания происхождения, NUMERIC, неизменяемые версии/принятые условия/события.
- Две конкурентные попытки атомарного резерва последней единицы: успешна одна; отрицательный запас запрещён.
- Идемпотентное истечение резерва и невозможность истечения отправленного заказа.
- Дедупликация уведомлений.
- **Настоящий worker** пересчитал ReceiptAccepted, повторную доставку и поздний возврат: количество 5, затем снова 5, затем 3. Outbox подтверждается после сохранения снимков.
- Будущее recorded_at не подтверждается worker преждевременно.
- Роль worker читает разрешённые данные, но не меняет цены/членство; разрешённая функция истечения работает.

FAQ-тесты проверили строгий флаг, утверждённые вопросы/варианты, нормализацию, fallback, направление динамических вопросов в обычные разделы, лимит длины, отсутствие сетевых API и постоянного хранения. Валидация пояснений отвергает неизвестные metric_id, произвольные числа/текст, гарантии и инструкции вместо утверждений.

Последняя проверка кода выявила и исправила несовпадение фильтров графика и пояснения: endpoint теперь принимает локацию и размер партии, кэш разделён по когорте/версии/происхождению, UI показывает пояснение только для выбранного SKU и текущей версии снимка. Собственные данные поставщика не передаются в LLM. Для ещё не рассчитанного изменения цены выводится «—». После правок повторная синтаксическая проверка: 42 файла, 0 ошибок. Проверка соответствующей ветки добавлена в Node integration, но **не выполнена** из-за отсутствующих зависимостей.

На момент проверки реализации в каталоге не было .git: `git status --short` возвращал «not a git repository», поэтому сравнение с предыдущей Git-историей было невозможно. Ранее созданные файлы сохранены и доработаны; исходные обновлённые спецификации с неканоническими именами также сохранены.

Локальный `git init` выполнился, но запись `.git/config` запрещена файловыми правами, а Git HTTPS недоступен. Для коммита и обновления удалённой ветки используется подключение GitHub; успешный push через CLI не заявляется. Перед публикацией проверены 93 файла: `.env`, локальная PostgreSQL-база, `.local/`, `.cache/` и сгенерированные файлы исключены; встроенных секретов в публикуемых файлах не обнаружено. `bro24.md` пока пуст; внешний чат ожидает документированный контракт.

## Не заявляется готовым

Полный web-прототип нельзя объявить проверенно работающим до установки зависимостей и запуска типов/сборки/интеграционных/E2E тестов. Не проверены визуальная компоновка в браузере, сессии/CSRF в реальном HTTP, весь Node-цикл заказа, seed через его Node CLI, закреплённые контейнеры, публичный деплой и восстановление backup.

Все исторические данные, поставщики и цены — demo. Реальные поставщики, платежи и внешние уведомления не подключены. OpenAI provider реализован как отключаемый ограниченный слой пояснений, но живой ключ/модель не проверялись. Обученной ML-модели, временного бэктеста, интервалов и заявлений о точности нет. FAQ реализован отдельно; UI-проверка клавиатуры/очистки истории остаётся в E2E.
